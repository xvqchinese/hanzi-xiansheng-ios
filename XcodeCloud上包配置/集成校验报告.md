## 二、需要处理的问题

### P0（阻塞 Xcode Cloud）：无共享 scheme

仓库 `DWKeyboard.xcodeproj` 内没有 `xcshareddata/xcschemes/`。Xcode Cloud 配置界面只能选择**共享 scheme**。
本包已附带生成好的 `DingShiApp.xcscheme`（blueprintID 与 pbxproj 实测一致：`4E807D9219461D9000D875D1` / DingShiApp.app），
提交方式见《XcodeCloud配置指南》第 1 节，一分钟可完成。

> 说明：GitHub Actions 的 compile-test 之所以能在无共享 scheme 下编译通过，是因为命令行 xcodebuild 会自动创建临时 scheme；Xcode Cloud 不做这件事，必须显式共享。

### P1（建议修复，1 行×3 处）：在线词库非原子写

`DingShiApp/DBUpdate.swift` 第 207、216、225 行，词库下载完成后 `write(to:options:[])` 为**原地覆写**。
词库加载改 mmap 后，键盘扩展会持有文件映射（尤其 `cn2enData` 常驻）；若此时主 App 覆写同路径文件，
键盘进程可能 SIGBUS 崩溃（触发条件苛刻：使用中恰好手动更新词库，但后果是闪退）。

建议修复（与本包 diff 风格一致的最小改动）：

```diff
- try? receivedData["py"]?.write(to: fileUrlFromGroup(file: "py.data"), options: [])
+ try? receivedData["py"]?.write(to: fileUrlFromGroup(file: "py.data"), options: .atomic)
```
（第 216 行 sk、第 225 行 cn2en 同法。原子写=先写临时文件再改名，旧映射继续有效，零风险。）

不修复也不阻塞编译与 TestFlight，仅存在上述小概率崩溃场景。

### P2（提示）：CI 日志在线核验受限

GitHub Actions 日志下载 API 需要仓库 admin 权限，本次以 run 结论（success）为准。
如需复核，仓库页面 → Actions → compile-test → 最新 run 可直接查看。
